## Выбранная реализация

Выбран небольшой работающий прототип с архитектурным описанием. Его можно
быстро прочитать и проверить локально. Основной акцент — последовательные попытки,
правила остановки каскада и защита от повторного выполнения операции.

- **Stripe Sandbox + mock.** Stripe действительно вызывается по HTTP через httpx.
  Mock имитирует отказ до обработки и позволяет показать безопасный переход к Stripe.
  Реальные деньги и карточные реквизиты не используются.
- **Два FastAPI endpoint:** `POST /v1/payments` и `GET /v1/payments/{payment_id}`.
- **Обработка внутри HTTP-запроса.** POST ожидает завершения каскада; отдельной
  фоновой задачи нет. Асинхронный HTTP-клиент не блокирует event loop при ожидании сети.
- **In-memory dict вместо PostgreSQL.** Это работающая упрощённая реализация хранения,
  а не эмуляция SQL: в памяти находятся параметры запроса, ключ, статус и попытки.
- **uv вместо Poetry.** Зависимости описаны в `pyproject.toml`, версии зафиксированы
  в `uv.lock`. Проект запускается из исходников без сборки устанавливаемого пакета.
- **Разделение по ответственности.** API, каскад, провайдеры и хранилище находятся
  в отдельных модулях. Полноценные DDD-слои и микросервисы для демки не вводились.

### Реализовано, заменено и оставлено за рамками

| Часть | Фактическое состояние |
| --- | --- |
| FastAPI, Pydantic, настройки из `.env` | Реализованы |
| Stripe Sandbox | Работающая интеграция создания/подтверждения платежа и чтения PaymentIntent |
| Mock-провайдер | Настраиваемая заглушка; в HTTP API всегда возвращает `unavailable` |
| Каскад и логирование попыток | Реализованы |
| Идемпотентность API | Реализована в памяти одного процесса |
| PostgreSQL, миграции, SQLAlchemy | Не реализованы; заменены dict, `models.py` и `repositories.py` — только поясняющие заглушки |
| Taskiq | `worker.py` — неиспользуемая заглушка, возвращает `not_implemented`; каскад не выполняет |
| Redis | Необязательный сервис Compose; приложение к нему не подключается |
| Docker | Написаны Dockerfile, Compose и `.dockerignore` в виде примера |
| JWT, S3, RunPod, Telegram, Google, NOWPayments | Не реализованы для демо |
| Автоматические повторы, webhooks, сверка неопределённых результатов | Не реализованы для демо |

## Правила каскадирования

| Результат провайдера | Значение | Действие |
| --- | --- | --- |
| `succeeded` | Успех подтверждён | Завершить успешно |
| `unavailable` | Гарантированный отказ до обработки, списания не было | Перейти к следующему |
| `failed` | Отказ или ошибка запроса, для которых автоматическое переключение не разрешено | Остановиться |
| `unknown` | Нет подтверждённого окончательного результата | Остановиться, требуется сверка |

Если все провайдеры вернули `unavailable`, итог платежа — `failed`.

Только mock возвращает `unavailable` в текущей реализации. Stripe не используется
как источник автоматически повторяемых ошибок: отказ карты останавливает каскад.
HTTP 400/401/402/403/404 Stripe отображаются в `failed`; прочие HTTP-ошибки,
сетевые ошибки и некорректный ответ — в `unknown`. Статусы PaymentIntent,
отличные от `succeeded`, тоже консервативно объединены в `unknown`.
Например, `requires_action` ещё не означает отказ: может потребоваться действие клиента.

Таймаут не доказывает отсутствие списания. Поэтому после таймаута не вызывается
другой провайдер и не генерируется автоматически новый ключ операции.
Автоматических повторов HTTP-запросов нет.

### Идемпотентность

API резервирует ключ и создаёт UUID со статусом `processing` **до** внешнего вызова.
Резервирование синхронное, без `await`: в одном event loop второй запрос увидит запись.

- Повтор с тем же ключом и теми же параметрами возвращает сохранённый платёж.
- Если первый запрос ещё выполняется, повтор возвращает `202` и `processing`.
- Изменение суммы, валюты, способа оплаты или порядка провайдеров при том же ключе — `409`.
- Неожиданное прерывание обработки сохраняет `unknown`, не освобождая ключ.
- Ключ передаётся Stripe как `Idempotency-Key`; защита Stripe и локальная защита API
  выполняют разные задачи.

Гарантии локального хранилища действуют только до перезапуска и в одном процессе.
GET читает сохранённый результат, не обновляет его из Stripe.

## HTTP API

### POST /v1/payments

```json
{
  "amount": 100,
  "currency": "EUR",
  "payment_method": "pm_card_visa",
  "idempotency_key": "review-fallback-001",
  "providers": ["mock", "stripe"]
}
```

| Поле | Правило |
| --- | --- |
| `amount` | Строго положительное целое число в минимальных единицах; 100 EUR-центов = 1 EUR |
| `currency` | Три заглавные латинские буквы, по умолчанию `USD`; проверяется формат, не каталог валют |
| `payment_method` | По умолчанию `pm_card_visa`; для проверки отказа — `pm_card_chargeDeclined` |
| `idempotency_key` | 1–255 символов: латинские буквы, цифры, дефис и подчёркивание |
| `providers` | Непустой список `mock` / `stripe` в порядке вызова; по умолчанию `["stripe"]` |

Ответ содержит `id` (UUID нашего платежа), `status`, `provider` (последний вызванный)
и `attempts`. В попытке Stripe `payment_id` — отдельный внешний ID вида `pi_…`.
Он не заменяет UUID для GET endpoint.

### GET /v1/payments/{payment_id}

Передайте UUID из ответа POST. Ответ: `id`, `status`, `provider`, `result`.
В текущей модели `result` дублирует `status`. Источник — локальный dict.

| HTTP-код | Значение |
| --- | --- |
| `201` | Новая запись обработана; её статус может быть `succeeded`, `failed` или `unknown` |
| `200` | Получение записи или повтор завершённого POST |
| `202` | Повтор POST, пока исходная операция находится в `processing` |
| `409` | Ключ уже занят запросом с другими параметрами |
| `422` | Ошибка входных данных, пустой маршрут или неизвестный провайдер |
| `404` | UUID не найден в памяти |

HTTP 201 не означает успешную оплату. Отказ Stripe HTTP 402 в этой модели API
возвращается внутри результата нового платежа как `201` + `status=failed`.

## Ручная проверка через Swagger UI

Нужен именно локальный Swagger UI FastAPI по `/docs`; заходить на swagger.io
или создавать там аккаунт не требуется.

### 1. Успех и безопасный fallback

1. Раскройте **POST /v1/payments**.
2. Нажмите **Try it out**.
3. Вставьте JSON из раздела HTTP API с ключом `review-fallback-001`.
4. Нажмите **Execute**. Посмотрите **Server response**, HTTP-код и **Response body**.
5. Ожидайте `201`, `succeeded` и две попытки: mock `unavailable`, Stripe `succeeded`.
6. Скопируйте верхнеуровневый `id` (UUID), а не `payment_id` внутри попытки Stripe.

Сценарий подтверждает, что второй провайдер вызывается только после разрешённого
безопасного исхода первого. Тестовая оплата — 1 EUR без движения реальных денег.

### 2. Чтение статуса

1. Раскройте **GET /v1/payments/{payment_id}**, нажмите **Try it out**.
2. В поле `payment_id` вставьте скопированный UUID, нажмите **Execute**.
3. Ожидайте `200` с тем же ID и статусом `succeeded`.
4. Передайте `missing`: ожидайте `404`.

Это проверка сохранения и поиска результата, а не сверка со Stripe.

### 3. Идемпотентный повтор

Повторите исходный POST без изменений: ожидайте `200`, тот же UUID и тот же
Stripe `payment_id`. Нового каскада быть не должно.
Измените только `amount` на `200`, оставив ключ: ожидайте `409`.
Для новой операции используйте новый ключ.

### 4. Отказ карты без вызова backup

В POST передайте:

```json
{
  "amount": 100,
  "currency": "EUR",
  "payment_method": "pm_card_chargeDeclined",
  "idempotency_key": "review-decline-001",
  "providers": ["stripe", "mock"]
}
```

Ожидайте `201`, `failed` и **одну** попытку Stripe. Mock не вызывается.
Повтор с теми же параметрами вернёт сохранённый отказ с кодом `200`.
Смысл проверки — отказ карты не запускает автоматическое переключение.

### 5. Недоступность всех провайдеров

В исходном JSON замените ключ на `review-unavailable-001`, а список — на `["mock"]`.
Ожидайте `201`, итог `failed`, одну попытку `unavailable`. Stripe не вызывается.

### 6. Валидация

Поочерёдно измените тело POST. Во всех случаях ожидается `422` до проведения платежа:

| Изменение | Что проверяется |
| --- | --- |
| `amount: 0` | Положительная сумма |
| `amount: 1.5` или `true` | Строго целочисленный тип |
| `providers: []` | Наличие хотя бы одного провайдера |
| `providers: ["missing"]` | Допустимые названия провайдеров |
| `idempotency_key: "   "` или `"платёж-001"` | Ключ содержит только латинские буквы, цифры, дефис и подчёркивание |
| `currency: "eur"` | Ожидаемый регистр и формат валюты API |

### 7. Неопределённый результат

API mock имеет фиксированный исход `unavailable`; переключателя `unknown` в Swagger нет.
Остановка каскада при `unknown`, таймауты и HTTP 500 проверяются
автоматическими тестами. Отдельного ручного сценария для них в Swagger нет.

Не меняйте ключ после настоящего таймаута ради повторного списания. Сначала требуется
проверить исход. Повтор прежнего POST в запущенном API вернёт сохранённую запись.

## Автоматизированные тесты

Используется стандартный `unittest` с `IsolatedAsyncioTestCase`.
Дополнительный pytest-плагин не требуется. Запуск из корня:

```powershell
uv run python -m unittest discover -s tests/unit -v
```

Ожидаемый результат текущего набора: **19 тестов, OK**. Параметризованные через
`subTest` варианты проверяются внутри этих 19 методов.
Сервер запускать не нужно; тесты не требуют `.env` или настоящего API-ключа.
HTTP Stripe подменяется `httpx.MockTransport`, API вызывается внутри процесса через
`httpx.ASGITransport`, для каждого API-теста создаётся отдельное хранилище.

### Что проверяется и зачем

| Файл / тест-кейс | Проверка | Смысл |
| --- | --- | --- |
| `test_stripe_client.py`: создание и чтение | URL, поля формы, ключ идемпотентности, разбор ответа | Клиент формирует ожидаемый запрос и извлекает результат |
| Ошибки 402 и 500 | Исключение передаётся вызывающему коду, одна попытка | Клиент не скрывает ошибку и не повторяет вызов |
| Таймаут | Передаётся `ReadTimeout`, одна попытка | Неопределённость не запускает повтор |
| Некорректная сумма | 0, отрицательная, bool, дробная — до HTTP | Ошибочный ввод не отправляется провайдеру |
| `test_cascade.py`: безопасный fallback | `unavailable` → backup, передача того же запроса | Следующий провайдер вызывается в разрешённой ситуации |
| Терминальные исходы | После `succeeded`, `failed`, `unknown` backup не вызывается | Успех и неопределённость не приводят к следующему списанию |
| Все недоступны | Итог `failed`, обе попытки учтены | Корректное завершение исчерпанного маршрута |
| Пустой маршрут | `ValueError` | Нельзя провести платёж без провайдеров |
| Результаты адаптера Stripe | Успех, `requires_action`, некорректный ответ, 402, 409, 500, таймаут | Преобразование в общие статусы и отсутствие вызова backup |
| `test_payments_api.py`: POST / GET / повтор | 201, чтение результата, 200 при повторе, один HTTP Stripe | Связность endpoint и идемпотентность API |
| Изменение параметров | Другая сумма или маршрут с прежним ключом — 409 | Защита от повторного использования ключа для другой операции |
| Валидация | Неверные суммы, маршрут и ключ — 422, без HTTP Stripe | Ошибки обнаруживаются до проведения |
| Недопустимый ключ | Кириллица, пробелы, спецсимволы, пустой или слишком длинный ключ — 422 | Ключ отклоняется до формирования HTTP-заголовка |
| Допустимый ключ | Латиница, цифры, дефис, подчёркивание; длина 1 и 255 | Ключ передаётся в заголовок Stripe без изменений |
| Mock → Stripe | Две попытки в верном порядке и успех | API правильно создаёт и соединяет адаптеры |
| Только mock | `failed`, без HTTP Stripe | Заглушка работает независимо от внешнего API |
| Конкурентный повтор | Пока первый запрос задержан, второй получает 202 и тот же UUID; один HTTP Stripe | Ключ резервируется до внешнего вызова |
| Повтор после unknown | HTTP 500 сохраняется как `unknown`, повтор не вызывает Stripe | Неопределённый результат не запускается заново |
| Несуществующий UUID | 404 | Контракт поиска платежа |

Для запуска одного файла:

```powershell
uv run python -m unittest discover -s tests/unit -p test_stripe_client.py -v
uv run python -m unittest discover -s tests/unit -p test_cascade.py -v
uv run python -m unittest discover -s tests/unit -p test_payments_api.py -v
```

Тесты с подменёнными ответами не подтверждают доступность Stripe и актуальность
внешнего контракта. Поэтому ручной запрос в Sandbox — отдельная проверка интеграции.
Долговременное хранение этими тестами не проверяется.

## Ограничения и дальнейшее развитие

- Данные, ключи и история теряются при перезапуске; несколько процессов имеют
  разные dict. Горизонтальное масштабирование не поддерживается.
- Нет автоматической сверки `unknown` со Stripe; требуется отдельная проверка.
- Нет JWT, разделения клиентов и защиты публичного API; демонстрационный запуск локальный.
- В API mock не подтверждает реальные платежи и не реализует собственное хранение.
- Stripe PaymentMethod привязан к Stripe. Перенос токенов между настоящими
  провайдерами и сбор платёжных данных не реализованы.
- Названия валют проверяются по формату; поддержку валюты и минимальную сумму
  для неё определяет Stripe.
- Пустые/шаблонные модули не означают наличие БД, очереди или отдельных mock-сервисов.

Для развития достаточно сначала заменить dict на PostgreSQL с уникальным ключом,
сохранением попытки до HTTP и защитой от конкурентной обработки. Затем добавить
сверку результатов через запросы статуса или проверенные webhooks.
Реальную очередь, аутентификацию и новые провайдеры следует добавлять по необходимости.
Эти улучшения описаны как возможные следующие шаги, а не как реализованные функции.
